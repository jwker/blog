## 1. Chat Completions（`openai-completions`）

OpenAI Chat Completions 是被最广泛实现的协议，多数「OpenAI 兼容」服务都是它的变体。

### 请求体顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `model` | string | 模型名 |
| `messages` | array | 消息列表，见下 |
| `tools` | array | 工具定义 |
| `tool_choice` | string / object | 工具选择策略 |
| `temperature` | number | 采样温度 |
| `max_tokens` | number | 输出上限，兼容旧服务时用 |
| `max_completion_tokens` | number | 输出上限，新版规范字段，与 `max_tokens` 二选一 |
| `stream` | boolean | 是否流式 |
| `stream_options` | object | 常用 `{"include_usage": true}` |
| `store` | boolean | 是否存储本次响应 |
| `stop` | string / array | 停止序列 |
| `top_p` | number | 核采样 |
| `frequency_penalty` | number | 频率惩罚 |
| `presence_penalty` | number | 存在惩罚 |
| `response_format` | object | 结构化输出 |
| `seed` | number | 随机种子 |
| `parallel_tool_calls` | boolean | 是否允许并行工具调用 |
| `metadata` | object | 附加元数据 |
| `service_tier` | string | 服务档位 |
| `user` | string | 终端用户标识 |
| `reasoning_effort` | string | 思考强度，见扩展字段一节 |
| `prompt_cache_key` | string | 提示缓存键 |
| `prompt_cache_retention` | string | 缓存保留时长，如 `"24h"` |

### 消息条目

| role | 关键字段 | 说明 |
|---|---|---|
| `system` | `content` | 系统指令，字符串 |
| `developer` | `content` | 开发者指令，与 `system` 语义相近但优先级更高，用于推理模型 |
| `user` | `content` | 字符串，或含图片的块数组 |
| `assistant` | `content`、`tool_calls` | 模型输出；`content` 是字符串或 `null` |
| `tool` | `tool_call_id`、`content` | 工具结果；部分服务还要求 `name` 标明工具名 |

请求体：

```json
{
    "model": "gpt-4o",
    "stream": true,
    "stream_options": {
        "include_usage": true
    },
    "messages": [
        {
            "role": "system",
            "content": "你是一个编码助手。"
        },
        {
            "role": "user",
            "content": "读一下 a.ts"
        },
        {
            "role": "assistant",
            "content": null,
            "tool_calls": [
                {
                    "id": "call_1",
                    "type": "function",
                    "function": {
                        "name": "read",
                        "arguments": "{\"path\":\"a.ts\"}"
                    }
                }
            ]
        },
        {
            "role": "tool",
            "tool_call_id": "call_1",
            "content": "export const a = 1;"
        }
    ],
    "tools": [
        {
            "type": "function",
            "function": {
                "name": "read",
                "description": "读取文件",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "path": {
                            "type": "string"
                        }
                    },
                    "required": [
                        "path"
                    ]
                }
            }
        }
    ]
}
```

### 内容块

用户消息带图片时 `content` 变成块数组，块类型是 `text` 和 `image_url`：

```json
{
    "role": "user",
    "content": [
        {
            "type": "text",
            "text": "看这张图"
        },
        {
            "type": "image_url",
            "image_url": {
                "url": "data:image/png;base64,iVBORw0KGgo..."
            }
        }
    ]
}
```

### 规范外的扩展字段

Chat Completions 的规范里没有思考内容的位置。

但各家服务商会自己加扩展字段：

**开关方向**——写在请求体里，告诉服务端「这次要不要思考、思考到什么程度」。这类字段只出现在请求里，响应里没有。

**载荷方向**——服务端在响应里用它把思考正文送回来。这类字段出现在响应的 delta 里；下一轮把历史发回去时，还要用同一个字段名把它带回去。

两类字段的分工：

| 字段 | 出现方向 | 形态 | 作用 | 常见于 |
|---|---|---|---|---|
| `reasoning_effort` | 请求 | string | 设定思考强度，取值 `minimal` / `low` / `medium` / `high` | OpenAI 风格的推理服务 |
| `reasoning` | 请求 | `{"effort": "..."}` | 设定思考强度 | OpenRouter、Together、Ant-Ling |
| `thinking` | 请求 | `{"type": "enabled" \| "disabled"}` | 开关思考 | DeepSeek、Z.AI |
| `thinking` | 请求 | string | 直接把思考等级写成字符串 | 某类把等级当字符串传的服务 |
| `enable_thinking` | 请求 | boolean | 开关思考 | Qwen |
| `chat_template_kwargs` | 请求 | object | 开关思考，常见 `{"enable_thinking": true, "preserve_thinking": true}` | 走 chat template 的服务 |
| `chat_template_args` | 请求 | object | 同上，字段名不同的变体 | 同上 |
| `reasoning_content` | 响应 | string | 承载思考正文 | DeepSeek，以及大量 OpenAI 兼容服务 |
| `reasoning` | 响应 | string | 承载思考正文 | llama.cpp 等本地推理服务 |
| `reasoning_text` | 响应 | string | 承载思考正文 | 另一类服务的叫法 |
| `reasoning_details` | 响应 | array of object | 承载思考正文，结构化条目 | OpenRouter |

注意 `reasoning` 这个名字在两个方向上都有，形态还不一样：请求里是 `{"effort": "high"}` 用来调档位，响应里是字符串用来装正文。别混用。

一轮对话里这三个环节连起来是这样：

第一步，请求体里放开关字段，决定这次思考的强度：

```json
{
    "model": "deepseek-chat",
    "reasoning_effort": "high",
    "messages": [
        {
            "role": "user",
            "content": "读一下 a.ts"
        }
    ]
}
```

第二步，响应的 delta 里，思考正文放在载荷字段里：

```json
{
    "choices": [
        {
            "delta": {
                "reasoning_content": "先读文件。"
            }
        }
    ]
}
```

第三步，下一轮把历史发回去，思考正文要用同一个载荷字段带回，放在 assistant 消息上：

```json
{
    "model": "deepseek-chat",
    "messages": [
        {
            "role": "user",
            "content": "读一下 a.ts"
        },
        {
            "role": "assistant",
            "content": "我先读一下文件。",
            "reasoning_content": "先读文件。"
        }
    ]
}
```

第三步就是容易困惑的地方：回传的字段名是「载荷方向」那个名字，但它出现在请求体里。因为服务端要求思考内容原样回传，字段名必须和第二步响应里用的完全一致，用错名字推理链就断了。

对不支持思考的服务，上面三个环节都省掉，请求里不放开关字段，响应里也没有思考正文。

另外几个非规范字段：`tool_stream`（布尔，部分服务用它开启工具调用流式返回）、`priority`（vLLM 的优先级）、`cache_control`（Anthropic 风格的缓存标记，经 LiteLLM 之类的网关透传）、`provider` 与 `providerOptions`（OpenRouter 与 Vercel AI Gateway 的路由偏好）。

### 约束

`assistant.content` 是字符串或 `null`，不是块数组。发块数组有些服务会原样模仿结构产出嵌套结果。

工具调用的 `arguments` 是 JSON 字符串，不是对象。

工具结果消息只承载文本。工具返回图片时，图片需要另发一条 `user` 消息承载，常见前缀是 `Attached image(s) from tool result:`。

### 工具结果带图片时的消息序列

工具同时返回文本和图片时，文本留在 `tool` 消息里，图片另起一条 `user` 消息。四条消息构成一次完整的往返：

```json
{
    "model": "gpt-4o",
    "messages": [
        {
            "role": "user",
            "content": "把截图里的数字读出来"
        },
        {
            "role": "assistant",
            "content": null,
            "tool_calls": [
                {
                    "id": "call_1",
                    "type": "function",
                    "function": {
                        "name": "screenshot",
                        "arguments": "{\"path\":\"shot.png\"}"
                    }
                }
            ]
        },
        {
            "role": "tool",
            "tool_call_id": "call_1",
            "content": "已截取屏幕，尺寸 1920x1080。"
        },
        {
            "role": "user",
            "content": [
                {
                    "type": "text",
                    "text": "Attached image(s) from tool result:"
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "data:image/png;base64,iVBORw0KGgo..."
                    }
                }
            ]
        }
    ]
}
```

如果工具只返回图片、没有文本，`tool` 消息仍然必须存在，用占位串撑住这条消息：

```json
{
    "role": "tool",
    "tool_call_id": "call_1",
    "content": "(see attached image)"
}
```

有些服务要求 `tool` 消息额外带 `name` 字段标明是哪个工具的结果：

```json
{
    "role": "tool",
    "tool_call_id": "call_1",
    "name": "screenshot",
    "content": "已截取屏幕，尺寸 1920x1080。"
}
```


## 2. OpenAI Responses（`openai-responses`）

OpenAI 较新的协议。消息字段叫 `input`，元素是 item 数组，用 `type` 区分种类。

### 请求体顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `model` | string | 模型名 |
| `input` | array | item 列表，见下 |
| `instructions` | string | 独立的指令字段，等价于开头的 developer 消息 |
| `tools` | array | 工具定义 |
| `tool_choice` | string / object | 工具选择策略 |
| `max_output_tokens` | number | 输出上限 |
| `temperature` | number | 采样温度 |
| `reasoning` | object | `{"effort": "...", "summary": "auto"}` |
| `include` | array of string | 常用 `["reasoning.encrypted_content"]` |
| `store` | boolean | 是否存储响应 |
| `previous_response_id` | string | 接着上一次响应继续 |
| `text` | object | `{"format": {...}}` 结构化输出 |
| `truncation` | string | 上下文超长时的截断策略 |
| `service_tier` | string | 服务档位 |
| `parallel_tool_calls` | boolean | 是否允许并行工具调用 |
| `metadata` | object | 附加元数据 |
| `prompt_cache_key` | string | 提示缓存键 |
| `prompt_cache_retention` | string | 缓存保留时长 |
| `background` | boolean | 异步任务模式 |

请求体：

```json
{
    "model": "gpt-5",
    "stream": true,
    "store": false,
    "reasoning": {
        "effort": "medium",
        "summary": "auto"
    },
    "include": [
        "reasoning.encrypted_content"
    ],
    "input": [
        {
            "role": "user",
            "content": [
                {
                    "type": "input_text",
                    "text": "读一下 a.ts"
                }
            ]
        },
        {
            "type": "message",
            "role": "assistant",
            "content": [
                {
                    "type": "output_text",
                    "text": "我先读一下文件。",
                    "annotations": []
                }
            ],
            "status": "completed",
            "id": "msg_abc"
        },
        {
            "type": "function_call",
            "id": "fc_abc",
            "call_id": "call_1",
            "name": "read",
            "arguments": "{\"path\":\"a.ts\"}"
        },
        {
            "type": "function_call_output",
            "call_id": "call_1",
            "output": "export const a = 1;"
        }
    ],
    "tools": [
        {
            "type": "function",
            "name": "read",
            "description": "读取文件",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {
                        "type": "string"
                    }
                },
                "required": [
                    "path"
                ]
            },
            "strict": false
        }
    ]
}
```

### item 类型

| `type` | 关键字段 | 说明 |
|---|---|---|
| `message` | `role`、`content`、`status`、`id` | 普通消息，`role` 为 `user` 或 `assistant` |
| `function_call` | `id`、`call_id`、`name`、`arguments` | 工具调用，`arguments` 是 JSON 字符串 |
| `function_call_output` | `call_id`、`output` | 工具结果 |
| `custom_tool_call` | `id`、`call_id`、`name`、`input` | 自定义语法工具的调用 |
| `custom_tool_call_output` | `call_id`、`output` | 对应的结果 |
| `reasoning` | `id`、`summary`、`encrypted_content` | 推理条目 |
| `computer_call` | `call_id`、`action` | 计算机操作 |
| `web_search_call` | `id`、`status` | 内置网页搜索 |
| `file_search_call` | `id`、`queries` | 内置文件检索 |
| `image_generation_call` | `id`、`result` | 内置图像生成 |
| `mcp_call` | `id`、`name`、`arguments` | MCP 服务调用 |
| `item_reference` | `id` | 引用此前某个 item |

### 内容块类型

| `type` | 出现位置 | 说明 |
|---|---|---|
| `input_text` | user 消息 | 输入文本 |
| `input_image` | user 消息 | 输入图片，`image_url` 带 data URL，`detail` 取 `auto` / `low` / `high` |
| `output_text` | assistant 消息 | 输出文本，带 `annotations` 数组 |
| `refusal` | assistant 消息 | 拒答 |
| `summary_text` | reasoning 摘要 | 推理摘要文本 |

### 推理条目的回放

Responses 是五种协议里唯一把思考做成独立 item 的。`reasoning` item 里 `encrypted_content` 是加密的思考内容，`include` 里加上 `reasoning.encrypted_content` 才会返回它。

多轮回放时，`reasoning` item 要原样放进 `input`，服务端才能接上推理链。

### id 与 call_id 的区别

`call_id` 用于把结果和调用配对，`id` 是 item 自身的标识。`function_call` 的 `id` 必须以 `fc_` 开头，`custom_tool_call` 必须以 `ctc_` 开头。`function_call_output` 只带 `call_id`。

跨模型复用历史时不要带 `id`，否则会触发服务端的 id 配对校验。


## 3. Anthropic Messages（`anthropic-messages`）

`system` 是独立字段，不混在消息里。`messages` 只有 `user` 和 `assistant` 两种 role。

### 请求体顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `model` | string | 模型名 |
| `max_tokens` | number | 必填，输出上限 |
| `system` | string / array | 系统提示，块数组时块类型为 `text` |
| `messages` | array | 消息列表 |
| `tools` | array | 工具定义 |
| `tool_choice` | object | `{"type": "auto" \| "any" \| "tool", "name": "..."}` |
| `temperature` | number | 采样温度 |
| `top_p` | number | 核采样 |
| `top_k` | number | 候选数限制 |
| `stop_sequences` | array of string | 停止序列 |
| `stream` | boolean | 是否流式 |
| `metadata` | object | `{"user_id": "..."}` |
| `service_tier` | string | 服务档位 |
| `thinking` | object | `{"type": "enabled" \| "disabled" \| "adaptive", "budget_tokens": 1024, "display": "summarized"}` |
| `output_config` | object | `{"effort": "high"}` |
| `betas` | array of string | 灰度特性开关 |
| `fallbacks` | array of object | 备用模型列表 |

请求体：

```json
{
    "model": "claude-sonnet-4",
    "max_tokens": 8192,
    "stream": true,
    "system": [
        {
            "type": "text",
            "text": "你是一个编码助手。"
        }
    ],
    "thinking": {
        "type": "enabled",
        "budget_tokens": 2048,
        "display": "summarized"
    },
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text",
                    "text": "读一下 a.ts"
                }
            ]
        },
        {
            "role": "assistant",
            "content": [
                {
                    "type": "thinking",
                    "thinking": "先读文件。",
                    "signature": "EqQBCgIYAh..."
                },
                {
                    "type": "text",
                    "text": "我先读一下文件。"
                },
                {
                    "type": "tool_use",
                    "id": "toolu_1",
                    "name": "read",
                    "input": {
                        "path": "a.ts"
                    }
                }
            ]
        },
        {
            "role": "user",
            "content": [
                {
                    "type": "tool_result",
                    "tool_use_id": "toolu_1",
                    "content": "export const a = 1;",
                    "is_error": false
                }
            ]
        }
    ],
    "tools": [
        {
            "name": "read",
            "description": "读取文件",
            "input_schema": {
                "type": "object",
                "properties": {
                    "path": {
                        "type": "string"
                    }
                },
                "required": [
                    "path"
                ]

        }

```

### 内容块类型

| `type` | 关键字段 | 出现位置 |
|---|---|---|
| `text` | `text` | user、assistant、system |
| `image` | `source` | user |
| `document` | `source` | user |
| `tool_use` | `id`、`name`、`input` | assistant |
| `tool_result` | `tool_use_id`、`content`、`is_error` | user |
| `thinking` | `thinking`、`signature` | assistant |
| `redacted_thinking` | `data` | assistant |
| `server_tool_use` | `id`、`name`、`input` | assistant |
| `web_search_tool_result` | `tool_use_id`、`content` | user |

图片块：

```json
{
    "type": "image",
    "source": {
        "type": "base64",
        "media_type": "image/png",
        "data": "iVBORw0KGgo..."
    }
}
```

### 扩展字段

`cache_control` 是 Anthropic 自己的扩展机制，标在需要缓存的块上：

```json
{
    "type": "text",
    "text": "很长的系统提示……",
    "cache_control": {
        "type": "ephemeral"
    }
}
```

它可以出现在 system 块、text 块、工具定义上。一个请求里通常只标一到两处，标记之后的上下文会被缓存。

`tool_addition` 和 `tool_removal` 是较新的工具动态变更块，出现在 system 消息里，用于在对话中途增删工具。

`fallbacks` 让模型出错时自动切到备用模型。

### 约束

工具结果必须紧跟对应的工具调用。`tool_result` 放在 user 消息里，且这条 user 消息要紧跟在含 `tool_use` 的 assistant 消息之后，中间插入其他内容会被拒绝。

思考块必须带 `signature` 原样回传。签名是服务端给的加密凭据，丢掉它就等于丢掉推理链。被安全策略屏蔽的思考会变成 `redacted_thinking` 块，`data` 里是不透明载荷。

工具结果的内容是字符串或块数组。错误结果里不能混图片。
